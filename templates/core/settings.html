Automatically approve passing PRs

When enabled, a complete review with passing required CI and no blocking findings submits a formal GitHub APPROVE review for the exact commit. It never merges or enables auto-merge.

Off by default. Enabling applies to new jobs; queued jobs keep their original policy. Disabling prevents approvals not yet submitted—it does not revoke existing valid approvals.

New commits invalidate the service’s approval and clear its approved label. Human reviews are not dismissed. Cleanup runs on webhooks, with periodic recovery; GitHub permissions must allow review dismissal. Enable GitHub’s stale-approval branch rule if you also need repository-enforced protection without waiting for the service.

The connected GitHub account cannot approve its own PRs. Those attempts need another reviewer. Existing approval requirements and merge rules still apply.
