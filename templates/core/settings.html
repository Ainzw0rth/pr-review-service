Changes apply to the policies shown above.

Policy details

Approval

Off by default. Enabling applies to new jobs; queued jobs keep their original policy. Disabling prevents approvals not yet submitted, but does not revoke existing valid approvals. The connected GitHub account cannot approve its own PRs; those attempts need another reviewer.

New commits invalidate the service’s approval and clear its approved label. Human reviews are not dismissed. Cleanup runs on webhooks with periodic recovery and needs GitHub review-dismissal permissions. Enable GitHub’s stale-approval branch rule for repository-enforced protection without waiting for the service.

Merging

Off by default. Requires the service’s formal approval, complete publication, passing CI and a clean GitHub merge state. Conflicts or missing requirements leave the PR open with a reason on its job. New settings do not apply to old approvals. There is one merge attempt after publication, no GitHub auto-merge scheduling and no branch deletion. Blocked or uncertain attempts need manual inspection.

Evidence

Default related-item limit: 50. Changes apply when evidence collection starts, including queued reviews. Running collections keep their captured limit. No item limit removes only this count cap; context-size and API safeguards remain. It does not enable recursive scanning of every issue.

Owner-only settings. Model order is managed in Workflow.
